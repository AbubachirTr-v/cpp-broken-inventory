# Практика C++: сломанный инвентарь

Вам передали рабочий по сборке, но неверный по поведению игровой инвентарь.
Нужно разобраться в чужом коде, найти ошибки и исправить их по требованиям.
Темы: классы, инкапсуляция, публичное наследование, виртуальные методы,
override, указатели, std::vector, поиск, граничные случаи и тестирование.

## Модель и правила времени жизни

`Inventory` хранит `Item*`, но **не владеет предметами**. Создавайте Weapon,
Armor и Potion как локальные объекты раньше инвентаря. Объекты должны
существовать при каждом обращении к ним через инвентарь. Не возвращайте
инвентарь с адресами локальных предметов из функции.
Удаление и очистка убирают только указатели, сами предметы продолжают жить.
Не нужны new, delete, умные указатели, clone и специальные операции перемещения.
Копирование инвентаря и предметов в задание не входит.

## Требуемое поведение

1. Item хранит имя и количество. Отрицательное количество в конструкторе
   и setQuantity превращается в 0. Имя сохраняется без изменений, включая пустое.
2. Weapon, Armor, Potion публично наследуют Item. Урон, защита и лечение
   доступны через методы чтения; отрицательные значения превращаются в 0.
3. Вызов use через Item* выбирает реализацию фактического класса.
   Используйте virtual и override; поля не должны быть публичными.
4. Item::use возвращает `Item: <имя>`, Weapon — `Attack: <имя>`,
   Armor — `Equip: <имя>`. Они не изменяют количество, даже если оно равно 0.
5. Potion::use при количестве больше 0 уменьшает его ровно на 1 и возвращает
   `Drink: <имя>`. При 0 возвращает `Empty: <имя>` и сохраняет 0.
   Префиксы содержат один пробел после двоеточия.
6. add возвращает true только при добавлении. nullptr и повторный адрес
   отклоняются с false, размер не меняется. Разные объекты с одинаковым именем разрешены.
7. size возвращает число зарегистрированных объектов, а не сумму количества.
8. at возвращает указатель по индексу от 0; вне диапазона — nullptr.
9. find ищет точное совпадение имени с учётом регистра, возвращает первый
   подходящий указатель или nullptr. Порядок совпадает с порядком добавления.
10. remove удаляет указатель по индексу и возвращает true. Неверный индекс
    даёт false без изменений. Порядок остальных элементов сохраняется.
11. useAll вызывает use каждого предмета один раз в порядке хранения
    и возвращает вектор сообщений. Для пустого инвентаря результат пустой.
12. clear делает инвентарь пустым; повторная очистка безопасна.

## Работа

1. Соберите проект и запустите демонстрацию и начальные тесты.
2. Сопоставьте код с требованиями. Не меняйте тесты ради зелёного результата.
3. Исправьте ошибки, сохранив имена классов и публичных операций.
4. Дополните tests.cpp: проверьте каждый пункт, пустой инвентарь, nullptr,
   дубликат адреса, одинаковые имена, отрицательные характеристики, нулевое
   количество зелья, неверные индексы и удаление первого/среднего/последнего.
5. Покажите вызовы через Item* и объясните время жизни объектов.

## Сборка (C++17, CMake 3.16+)

Установите компилятор C++ (например, Visual Studio с компонентом
«Разработка классических приложений на C++») и CMake.
Из каталога проекта выполните:

```sh
cmake -S . -B build
cmake --build build --config Debug
ctest --test-dir build -C Debug --output-on-failure
```

Демонстрация: `build/Debug/inventory_demo.exe` для Visual Studio;
для генератора с одной конфигурацией — `build/inventory_demo`.
Начальные тесты намеренно не проходят на исходнике. Они не покрывают всё условие.

## Что сдавать

В собственном учебном репозитории: исправленный код, дополненные тесты,
краткий отчёт «ошибка → причина → исправление → проверка» и команды сборки.
Не отправляйте исправления в репозиторий задания. Не добавляйте build и исполняемые файлы.
Готовность: сборка успешна, ваши тесты проходят, все требования выполнены,
на защите вы объясняете полиморфизм и почему Inventory не удаляет предметы.
